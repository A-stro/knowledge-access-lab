# Knowledge Access

Comparative knowledge architectures. **The same questions are answered through four different retrieval systems — RAG, wiki/MCP, knowledge graph, and direct retrieval — over one shared corpus, and the results are scored on evidence quality, not vibes.**

The retrieval-architecture debate is usually argued, not measured: real systems pick a philosophy (semantic search will suffice; structure is the interface; graphs are overkill) without comparative numbers. This project gives it numbers.

## The demonstration

On a fresh clone, one command runs the forty-five-question gold set through all five lanes over the same synthetic second-brain corpus and commits the measured differences:

- **Per-lane × per-category evidence-quality results with receipts** — three lanes return passages, so citation fidelity is gradeable from tool results alone (byte-exact, transport-normalized); the two graph lanes are traversal-shaped — paths, typed edges, and (seeded) name→path metadata, never record text — and the comparison measures exactly that architectural difference.
- **Architecture is the variable; model is the constant.** The agent-under-test model is pinned; only the retrieval architecture differs between runs.
- **Reproducible evidence.** Pinned tooling, a committed embedding index (build-time-only model dependency), and committed run artifacts — anyone cloning gets the same numbers.

The resume story: this project shows the author can design a fair comparative eval — same data, same rules, same grader across four architectures — and report what actually won, per category, with the artifacts to back it.

## The results

The full suite — all 45 gold questions × all five lanes, 225 cells, one neutral trace + one scored verdict each — is committed (224 settled; one recorded non-settlement, below), and the rollup reports both axes — deterministic evidence fidelity and blind-judged answer agreement — per lane × per category, with per-question receipts:

**Judged answers — correct ratio (correct/partial/incorrect; graph-seed's multi-hop is over its 8 settled cells):**

| lane | point-lookup | multi-hop | synthesis | temporal | absence | all |
|---|---|---|---|---|---|---|
| rag | 1.00 | 0.78 | 0.56 | 0.67 | 1.00 | **0.80** |
| wiki | 1.00 | **0.89** | 0.44 | **0.78** | 0.67 | 0.76 |
| graph | 0.00 | 0.00 | 0.00 | 0.00 | **1.00** | 0.20 |
| graph-seed | 0.00 | 0.25 | 0.00 | 0.00 | 0.78 | 0.20 |
| direct | 1.00 | 0.78 | **0.78** | **0.78** | 0.44 | 0.76 |

**Evidence fidelity — passage-exact / record-found means:** direct **0.96** · wiki **0.92** · rag **0.89** · graph **0.00** · graph-seed **0.00** (both graph lanes by architecture — the accepted framing: they return paths, typed edges, and name→path metadata, never record text; graph-seed's record-found mean is 0.97, the naming axis the framing predicted could move).

What actually won, per category, with the artifacts to back it:

- **The control group wins citation fidelity.** Native grep/read retrieved gold passages byte-exactly better than every "smart" surface (0.96) — with rag (0.89) last of the three evidence-capable lanes.
- **No lane wins judged answers overall.** RAG edges the total (0.80), but per category the winners split: wiki takes multi-hop (0.89) and ties temporal (0.78) — structure earns its keep on exactly the chain-traversal questions it was designed for — while direct takes synthesis (0.78) and all three tie point-lookup (1.00).
- **The pure graph surface never entered its own graph.** 0 of its 905 tool calls succeeded: every call needs a corpus record path, the questions carry names and titles instead, and the lane has no listing or seed tool — so every guessed path failed with "record not found" and no edge was ever traversed. Its judged-answer zero on all evidence categories is dominated by that cold-start lockout, not by the lack of record text (though it scores zero on passage fidelity by architecture either way). Its lone win — absence, 9/9 — is total failure producing the right answer.
- **Absence separates the honest from the thorough.** Every evidence-capable lane found something plausible on 2 of 9 evidence-free questions and answered instead of reporting no evidence; brute-force direct was worst (judged 0.44 on absence — it greps up convincing-looking non-answers). The bare graph lane, which cannot read anything, stated "no evidence found" perfectly (9/9) — and the seeded lane, which also cannot read anything but now has an entry point, stated it on only 7/9: given a way in, it answered two absence questions and was graded partial for it.
- **Cost shapes the philosophy.** RAG answered in the fewest steps (9.4 mean); direct burned the most steps (27.5) and bytes; wiki carried the heaviest payloads (19.7 KB mean — full records and the tree); the bare graph lane issued 20 calls per question that all failed in ~1 KB each.

What F6 added — the seeded graph lane (`lookup` + the frozen traversal surface), the multi-hop test the bare lane never got:

- **Seeding fixed the bootstrap, exactly as the receipts predicted.** The bare lane's 905 calls were 905 failures; the seeded lane's 44 settled cells ran ~1,500 calls with **4 errors total**. Record-found fidelity moved from 0.00 to **0.97** — the axis the accepted framing said could move — while passage fidelity stayed **0.00**, the axis it said could not. Both graph lanes score zero on passages by architecture; only their judged answers stand on their own.
- **The judged total barely moved; its character inverted.** Both graph lanes sit at 0.20 correct overall, but the composition is opposite: the bare lane's 9 correct are all absence refusals; the seeded lane's are 7 absence + **2 real multi-hop answers**, with 15 partials. On multi-hop the seeded lane is the only graph-family lane with correct answers (2 correct + 5 partial + 1 incorrect of 8 settled) — yet far from wiki's 0.89: structure identifies the chain, it cannot quote it.
- **Structure answers structure, not text.** The seeded lane's ceiling is "partial": point-lookup collapses (0 correct, 8 incorrect — a point-lookup needs the record's words), multi-hop and synthesis produce partials that name the right records and edges without the findings. Every partial rationale names records the lane found and passages it could not read.
- **The seeded lane fails slow.** One cell (q-mh-08) never settled: 5 attempts, ~5.7 h of agent time, diagnosed live as unbounded exploration — it resolves the cited records, then hunts for a way to read their text, which no seeded tool returns. Where the bare lane failed fast (20 steps to an honest refusal), the seeded model fails slow. That non-settlement is recorded in [results/unsettled.json](results/unsettled.json), carried in the rollup, and pinned by probe — the only cell in the suite not measured by verdict.
- **One measured caveat on the F6 judged axis:** 20 of the 44 seeded answers name their own tools ("the available graph tools only return record paths and titles"), so the blind judge can infer the architecture family from the answer text. No answer names the lane, and the judge grades answer-vs-gold agreement only — the caveat is real, pinned in ISC-19's probe, and reported here rather than assumed away.

Full tables, framing, and pinned models: [results/rollup.md](results/rollup.md) · per-question receipts: [results/rollup.json](results/rollup.json). Judge verdicts are receipts recorded at score time; every evidence number re-derives deterministically from the committed traces.

## The lanes

Every lane reads the identical committed corpus tree through its own tools. No lane gets privileged access, bash, web, or edit capability: lane runs are retrieval-only.

| Lane | Surface | Tools |
|------|---------|-------|
| RAG | in-repo MCP server | `semantic_search` (ranked passages + record paths over the committed index), `get` |
| Wiki | in-repo MCP server | `list` (tree + genre taxonomy), `open` (record), `links` (outgoing **and** incoming) |
| Graph | in-repo MCP server | `neighbors`, `paths` (traversal over five typed edges) |
| Graph, seeded (F6) | in-repo MCP server | `lookup` (name/title → record paths + titles, **never record text**) plus the frozen `neighbors`, `paths` |
| Direct | native-tool allowlist | `read`, `grep`, `find`, `ls` — the control group |

The MCP lanes are wired through the project `.pi/mcp.json`; the direct lane is the harness's native-tool allowlist. The project deliberately uses **zero custom harness extensions** — the runner loads only the harness's built-in MCP support, and only for the MCP lanes — which is what makes the lab portable across harnesses: the runner drives the reference harness behind a `HarnessDriver` interface and emits neutral, harness-agnostic traces.

## The corpus

One markdown + frontmatter tree under `corpus/`, in the second-brain genre — project notes, decision records, session summaries, meeting notes, people and org notes, and reference notes. Seven genres:

`projects/ · decisions/ · sessions/ · meetings/ · people/ · orgs/ · references/`

Every record carries frontmatter (`id`, `genre`, `title`, `created`, `provenance`, optional `tags`) and may carry curated typed links in `related:`, authored at write time — never extracted — using exactly five edge types:

`mentions · influenced_by · supersedes · contradicts · relates_to`

The corpus tells one coherent fictional story (a small studio, its clients, and its projects over several months). It is hand-authored at its core and expanded by a committed deterministic generator for distractor density (~200 records). Every record is marked `provenance: hand-authored` or `provenance: generated`.

> All people, organizations, places, and events in the corpus are fictional, with invented names. The corpus contains no real personal data.

## The gold set

`questions/gold.json` holds ≥40 hand-verified questions in five categories (~8 each), each with a gold answer and gold citations (record path + exact supporting passage):

- **point-lookup** — a single fact in a single record
- **multi-hop** — answers that require traversing `influenced_by` / `supersedes` / `contradicts` chains (the edges graph traversal should win on)
- **synthesis** — answers combined across multiple records
- **temporal** — answers depending on dates and ordering
- **absence** — questions with **no** supporting evidence anywhere in the corpus; the gold answer is "no evidence found" and the gold citation is empty by design

The gold set passes one human gate (principal review) before the first full suite run.

## Commands

```bash
bun install          # install tooling (bun + TypeScript)
bun test             # run all integrity probes (217 tests across 16 files)
bun run lint:corpus  # corpus lint alone (ISC-5)
bun run lint:gold    # gold lint alone (ISC-6)
bun run lab help     # lab CLI (run / score / suite / dry-run)
```

`build:index` (embedding index) is live — a build-time-only step against the pinned local endpoint (`EMBED_MODEL=<fp16 serving copy> python3 build/build_index.py`); the committed index lets any clone run the lanes with no model stack, and `--check` verifies byte-identical rebuilds. `lab run` (single question × lane) is live and emits a neutral trace into `results/runs/<lane>/<question>.json` — the direct lane runs inside a throwaway corpus-only sandbox, so its native tools can see nothing but the corpus. `lab score --lane <lane> --question <id>` grades one committed trace: deterministic evidence scoring (exact-passage + record retrieval from tool results alone) plus a blind-judge verdict on answer agreement; scores land in `results/scores/<lane>/<question>.json`. `lab suite [--jobs N]` runs the full comparative experiment — every lane × the whole gold set in one execution — and writes the rollup (`results/rollup.json` + its human render, `results/rollup.md`) built from the complete, validated cell set. The suite is resumable: cells with valid committed artifacts are reused, a killed suite loses nothing, and the rollup is written only when coverage is complete. The harness binary is `pi` from PATH (override with `PI_BIN`).
